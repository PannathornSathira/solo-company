# Phase 1 — Module 07 (P1-M07): Objective, Plan Review, Work Board, and Run UI

## 1. Objective and Owner

- **Owner**: Gemini
- **Objective**: Implement the complete user interface flow for objective intake, Chief of Staff plan review and approval, company work board inspection, and real-time SSE-driven run monitoring in `apps/web`. The owner can complete the full lifecycle from submitting an objective to viewing finished work items, executive briefs, and artifacts without refreshing the page.

## 2. Scope

### Allowed Changes
- Web application pages in `apps/web/app/` (`/objectives/new`, `/objectives/[id]/plan`, `/work`, `/runs/[id]`).
- UI components in `apps/web/components/` (`RunTimeline.tsx`, etc.).
- REST API client and runtime type definitions in `apps/web/lib/api-client.ts`.
- Phase 1 documentation in `docs/` (`docs/modules/phase-1/p1-m07.md`, `docs/roadmap/01-phase-1-single-company-mvp.md`).

### Excluded Changes
- Backend FastAPI contracts (`contracts/openapi.yaml`) or route implementations (`apps/api/app/routers/`).
- Database schema revisions or migrations (`apps/api/alembic/`).
- Execution coordinator or LangGraph workflow logic (`apps/api/app/runtime/`).

## 3. Approved Contracts & API Client Integration

P1-M07 strictly consumes the API contracts verified in P1-M06:
- **Objective Intake**: `POST /api/objectives` creates an objective; `POST /api/objectives/{id}/plan` generates a proposed work plan from the Chief of Staff agent.
- **Plan Review & Approval**: `POST /api/objectives/{id}/plan/revise` records revision feedback; `POST /api/objectives/{id}/plan/approve` submits plan approval with an `Idempotency-Key` UUID header, returning the created `AgentRun`.
- **Work Board**: `GET /api/work-items` retrieves items across all 6 durable lifecycle states (`proposed`, `approved`, `running`, `review`, `done`, `failed`).
- **Run Inspection**: `GET /api/runs/{id}`, `GET /api/runs/{id}/events`, and `GET /api/runs/{id}/artifacts` provide initial inspection state.
- **SSE Real-Time Stream**: `GET /api/runs/{id}/stream?after_sequence={lastSequence}` emits persisted `RunEvent` envelopes as real-time server-sent events.
- **Same-Run Retry**: `POST /api/runs/{id}/retry` with an `Idempotency-Key` UUID header resumes failed runs without discarding completed work or artifacts.

## 4. UX & State Flow

1. **Objective-to-Run Navigation**:
   - The user submits an objective on `/objectives/new`, which calls `createObjective` and `createPlan`.
   - Upon completion, the app redirects automatically to `/objectives/[id]/plan`.
   - Clicking **Approve Plan & Execute** calls `approvePlan` with an idempotency key and navigates immediately to `/runs/[id]` to render the initial `running` state.
2. **SSE Deduplication & Timeline Replay**:
   - `/runs/[id]` establishes an `EventSource` connection to `/api/runs/{id}/stream?after_sequence={maxSequence}`.
   - All 12 domain event types are handled and deduplicated by `sequence` number.
   - When an `artifact.created` or terminal run event occurs, `listRunArtifacts` is invoked to refresh live artifact content.
3. **Same-Run Retry UX**:
   - When `AgentRun.retryable` is `true`, a **Retry Run** button is displayed.
   - Clicking retry sends `POST /api/runs/{id}/retry` with a fresh idempotency key and reconnects the SSE stream, preserving the existing event timeline and artifacts.
4. **Offline Demo Fallback**:
   - If the backend API is disconnected, pages gracefully fall back to local fixtures in `apps/web/lib/fixtures.ts` without crashing.

## 5. Acceptance and Verification

- **Automated Verification**:
  ```bash
  pnpm test    # runs API pytest tests and web TypeScript tsc --noEmit check
  pnpm build   # verifies Next.js web application production bundling
  ```
- **Manual End-to-End Verification**:
  1. Start backend and web servers: `pnpm dev:api` and `pnpm dev:web`.
  2. Create an objective on `http://localhost:3000/objectives/new`.
  3. Approve the proposed plan on the plan review page and observe immediate redirection to the run inspection timeline.
  4. Watch real-time SSE events populate the timeline and inspect generated markdown artifacts.

## 6. Definition of Done

- Every page in the objective-to-run flow interacts with backend endpoints via `apps/web/lib/api-client.ts`.
- SSE events are deduplicated cleanly by sequence number and update timeline state in real time.
- Idempotency keys are sent for plan approval and retry claims.
- `pnpm test` and `pnpm build` pass with zero type or build errors.
