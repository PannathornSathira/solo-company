# P1-M02 — Web shell and static product states

## Module brief

- Owner: Gemini
- Objective: establish the Phase 1 owner console web shell, design system, navigation, and all primary static product states across the seven required routes using static fixtures aligned with P1-M01 contracts.

## Allowed files

- `apps/web/app/globals.css` design system styling;
- `apps/web/lib/fixtures.ts` static datasets matching Phase 1 OpenAPI contracts;
- `apps/web/lib/StateContext.tsx` demo state switcher store;
- `apps/web/components/*` reusable UI components (`Navigation`, `AgentCard`, `WorkBoard`, `RunTimeline`, `StateContainer`);
- `apps/web/app/*` responsive App Router routes;
- `docs/modules/phase-1/p1-m02.md` (this handoff).

## Excluded files and behavior

- database models, migrations, repositories, and CRUD handlers (`apps/api`);
- modifications to `contracts/openapi.yaml`, `ADR-001`, or `ADR-002`;
- LangGraph runtime orchestration, live SSE streams, and provider model integrations;
- user authentication, billing, multi-company switching, or scheduled background autonomy.

## Approved contracts

- API: `contracts/openapi.yaml`
- Events and artifacts: ADR-002 and `app.contracts.events.RunEvent`
- Architecture: ADR-001

All static fixture data models in `apps/web/lib/fixtures.ts` conform strictly to the schemas defined in `contracts/openapi.yaml` (`Company`, `AgentDefinition`, `Objective`, `WorkItem`, `AgentRun`, `RunEvent`, `Artifact`).

## Dependencies and assumptions

- Node.js 22+, pnpm 11+, Python 3.12+, and uv;
- `apps/web` running on Next.js 16 with App Router and React 19;
- no backend persistence or paid API key is needed to verify this static module.

## Acceptance commands

```bash
pnpm install
pnpm test
pnpm build
pnpm dev:web
```

Acceptance requires:
1. `pnpm test` (`test:api` via pytest and `test:web` via `tsc --noEmit`) to pass without type or syntax errors;
2. `pnpm build` to successfully create the production web bundle;
3. All seven primary routes (`/`, `/objectives/new`, `/objectives/[id]/plan`, `/work`, `/runs/[id]`, `/agents/[id]`, `/settings/company`) to render responsive layouts and minimum required content;
4. Support for interactive verification of `completed`, `loading`, `empty`, and `error` states across all routes.

## Definition of done

- The seven required Phase 1 screens are implemented with rich aesthetics, responsive glassmorphic cards, and clean typography (`Inter` / `Outfit`).
- Work board Kanban columns (`proposed`, `approved`, `running`, `review`, `done`, `failed`) render work items accurately.
- Run timeline renders ordered events with plain-text summaries without claiming to reveal private model reasoning.
- Demo switcher allows testing loading skeletons, empty states, and error alerts across any route.
- No database, OpenAPI, or event contract files were modified.

## Decisions requiring a new ADR

- adding a new deployable or client dependency beyond the approved stack;
- modifying event vocabularies, payload limits, or database constraints;
- changing the cross-module OpenAPI contract in `contracts/openapi.yaml`.
