# P1-M01 — Architecture, contracts, and repository bootstrap

## Module brief

- Owner: GPT
- Objective: establish the smallest bootable monorepo and freeze the Phase 1
  API, run-event, artifact, and database boundaries for later modules.

## Allowed files

- root repository configuration and documentation;
- `apps/api` bootstrap, contract model, fixture, and contract test;
- `apps/web` boot screen and build configuration;
- `contracts`;
- `infra/compose.yaml`;
- `docs/architecture` and this handoff.

## Excluded files and behavior

- database models, migrations, repositories, and CRUD handlers;
- product UI routes beyond the boot screen;
- LangGraph, prompts, model adapters, generated clients, and SSE behavior;
- authentication, RAG, tools, local models, and background workers.

## Approved contracts

- API: `contracts/openapi.yaml`
- Events and artifacts: ADR-002 and `app.contracts.events.RunEvent`
- Architecture: ADR-001

All IDs are UUIDs. All timestamps are timezone-aware ISO 8601 values. Business
records carry `company_id`.

Database names and minimum columns are:

| Table | Required columns |
| --- | --- |
| `companies` | `id`, `name`, `description`, `mission`, `working_rules`, timestamps |
| `agent_definitions` | `id`, `company_id`, `slug`, `name`, `role`, `objective`, `responsibilities`, `runtime_model_alias`, `prompt_version`, `enabled`, timestamps |
| `objectives` | `id`, `company_id`, `title`, `desired_outcome`, `context`, `constraints`, `status`, timestamps |
| `work_items` | `id`, `company_id`, `objective_id`, `parent_id`, `assigned_agent_id`, `title`, `instructions`, `deliverable_type`, `status`, `position`, timestamps |
| `agent_runs` | `id`, `company_id`, `objective_id`, `status`, `graph_version`, `started_at`, `finished_at`, `error_code`, timestamps |
| `run_events` | `id`, `company_id`, `run_id`, `sequence`, `event_type`, `summary`, `payload_json`, `created_at` |
| `artifacts` | `id`, `company_id`, `run_id`, `work_item_id`, `artifact_type`, `title`, `content_markdown`, `version`, timestamps |

Required database constraints for P1-M03 are unique agent slug per company,
unique event sequence per run, positive work-item position and artifact
version, and foreign keys that preserve `company_id` scoping.

Phase 1 is a trusted single-owner local deployment and has no user identity.
Authorization means company-scoped repository access; internet exposure
requires an identity ADR and is out of scope.

## Dependencies and assumptions

- Node.js 22+, pnpm 11+, Python 3.12+, uv, and Docker;
- one PostgreSQL 17 service;
- no paid API or runtime model is needed for this module.

## Acceptance commands

```bash
pnpm install
uv --directory apps/api sync
pnpm test
pnpm build
pnpm dev:web
pnpm dev:api
```

Acceptance requires the web and API to boot, `/api/health` to return
`{"status":"ok"}`, and the deterministic fake event fixture to pass the event
contract including its payload size limit.

## Definition of done

- ADR-001 and ADR-002 are accepted.
- The OpenAPI contract covers the Phase 1 endpoint surface.
- The fake event fixture validates without any paid service.
- Both applications boot from a clean dependency install.
- This handoff records verification and the exact P1-M02/P1-M03 dependency.

## Decisions requiring a new ADR

- a new deployable or database;
- a changed event vocabulary, payload limit, ordering rule, or artifact format;
- authentication or public deployment;
- an API contract change that affects another module.
