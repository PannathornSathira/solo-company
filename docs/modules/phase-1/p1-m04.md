# Phase 1 — Module 04 (P1-M04): Company and Agent Profile UI

## 1. Objective & Scope

Module `P1-M04` implements the Company and Agent Profile UI for the Phase 1 Single-Company MVP Next.js owner console (`apps/web`). It connects the static design shell from `P1-M02` with the REST API client and OpenAPI types generated in `P1-M03`, enabling live data consumption, interactive profile editing, visible validation and failure states, and offline resilience.

### Key Responsibilities
- Integrate `getCompany` and `updateCompany` from `apps/web/lib/api-client.ts` into `apps/web/app/settings/company/page.tsx` (`CompanySetupPage`).
- Enable editing of company `name`, `description`, `mission`, and `working_rules` with line-separated textarea parsing (`max_length=20`).
- Integrate `listAgents`, `updateAgent`, and `listWorkItems` from `apps/web/lib/api-client.ts` into `apps/web/app/agents/[id]/page.tsx` (`AgentProfilePage`).
- Introduce an interactive **"Edit Agent Profile"** mode allowing operators to modify editable fields defined in `AgentUpdate` (`name`, `role`, `runtime_model_alias`, `prompt_version`, `objective`, `responsibilities`, and `enabled` status).
- Upgrade the console dashboard (`apps/web/app/page.tsx`) to synchronize with live company and agent profiles so edits persist across routes.
- Implement clear visual feedback: success banners when edits persist, prominent error alerts when validation or API calls fail, and offline fixture fallbacks (`⚡ Offline Mode`) if the backend API is unreachable.

## 3. Key UI & Client Integrations

1. **Company Profile & Rules Persistence (`/settings/company`)**:
   - On mount, `CompanySetupPage` attempts to fetch the seeded company via `getCompany()`.
   - Operators can modify the brand name, description, mission statement, and operational working rules.
   - Client-side validation checks empty required fields and enforces a maximum of 20 working rules before submitting `PATCH /api/company`.
   - Successful updates trigger an emerald success banner (`Company settings saved successfully!`) and immediately update UI state.

2. **Specialist Agent Editing (`/agents/[id]`)**:
   - `AgentProfilePage` resolves specialist agents by slug or UUID using `listAgents()` and fetches assigned deliverables using `listWorkItems()`.
   - Clicking **"✎ Edit Profile"** opens an inline editable form card where operators can update `name`, `role`, `runtime_model_alias`, `prompt_version`, `objective`, `responsibilities` (one per line), and toggle the checkbox for **Agent Enabled & Ready for Work Assignments**.
   - Saving calls `PATCH /api/agents/{agent_id}`; success and error states are visibly displayed.

3. **Offline & Fallback Resilience**:
   - To guarantee that static UI verification and frontend demos remain functional when the local FastAPI server (`http://localhost:8000`) is offline, pages catch network errors, display a subtle `⚡ Offline Mode` badge, and fallback to `sampleCompany` / `sampleAgents` from `apps/web/lib/fixtures.ts`.
