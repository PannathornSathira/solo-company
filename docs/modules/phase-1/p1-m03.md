# Phase 1 — Module 03 (P1-M03): Persistence & API CRUD Layer

## 1. Objective & Scope

Module `P1-M03` implements the database persistence and REST CRUD API layer for the Phase 1 Single-Company MVP modular monolith (`apps/api/`). It bridges the accepted OpenAPI contract (`contracts/openapi.yaml`) and the PostgreSQL 17 relational database schema (`infra/compose.yaml`) via SQLAlchemy 2.0 ORM models and Alembic database migrations.

### Key Responsibilities
- Define SQLAlchemy 2.0 declarative models for all seven Phase 1 tables (`companies`, `agent_definitions`, `objectives`, `work_items`, `agent_runs`, `run_events`, `artifacts`) with company scoping, UUID primary keys, and required database constraints.
- Configure Alembic and generate the initial database migration (`0001_initial_schema.py`).
- Implement Pydantic validation schemas in `apps/api/app/contracts/` matching `contracts/openapi.yaml`.
- Create a repository layer (`company_repo.py`, `agent_repo.py`, `objective_repo.py`, `work_item_repo.py`) with automatic seeding of the default company and specialist agents, as well as state transition validation for objectives and work items.
- Implement FastAPI REST routers (`company.py`, `agents.py`, `objectives.py`) and wire exception handlers for OpenAPI-compliant error JSON responses (`404 Not Found`, `409 Conflict`, `422 Validation Error`).
- Add comprehensive `pytest` test suites (`test_company_crud.py`, `test_agents_crud.py`, `test_objectives_crud.py`) using in-memory SQLite with `StaticPool` for fast, deterministic unit and integration testing.
- Generate OpenAPI TypeScript types (`apps/web/lib/api-types.ts`) and create a typed client wrapper (`apps/web/lib/api-client.ts`) for the Next.js owner console.

## 3. Database Architecture & Alembic Schema

1. **Company Scoping & UUIDs**:
   - All Phase 1 domain tables include a `company_id` UUID column with index and foreign key referencing `companies.id (ON DELETE CASCADE)`.
   - Primary keys use `sa.Uuid(as_uuid=True)` for seamless compatibility across SQLite (in testing) and PostgreSQL (in local runtime).
2. **Timezone-Aware UTC Datetimes**:
   - Implemented a `UTCDateTime` SQLAlchemy `TypeDecorator` in `models.py` ensuring that naive UTC datetimes returned by database drivers are automatically converted to timezone-aware UTC datetime objects.
3. **Constraints**:
   - `uq_agent_definitions_company_slug`: Unique constraint on `(company_id, slug)` in `agent_definitions`.
   - `uq_run_events_run_sequence`: Unique constraint on `(run_id, sequence)` in `run_events`.
   - `ck_work_items_positive_position`: Check constraint `position >= 1` in `work_items`.
   - `ck_artifacts_positive_version`: Check constraint `version >= 1` in `artifacts`.

## 5. Handoff & Next Steps

With `P1-M03` completed, the database schema, CRUD endpoints, seeding, and typed frontend client are established.

- `P1-M04` will build on top of `objective_repo.py` and `work_item_repo.py` to create the objective approval and sequential work item plan generation workflow.
- When an objective transitions to `"approved"`, `P1-M04` can invoke the Chief of Staff agent prompt definition from `agent_repo.py` and persist generated work items into `work_items`.

### Handoff to P1-M05 (Next.js Owner Console UI Integration)
- `P1-M05` can import the typed API client from `apps/web/lib/api-client.ts` to replace static sample fixtures with live server data in `apps/web/app/` pages.
