# Solo Company Platform — Phase 1 End-to-End Demo Walkthrough

This guide provides a complete, step-by-step walkthrough of the **Phase 1 (Single-Company MVP)** demo. You can execute this entire flow from a clean checkout without reading source code or supplying paid API keys.

---

## 1. Demo Prerequisites & Startup

Open two terminal windows in the repository root:

### Terminal 1: Start Backend API Service
```bash
# Start local PostgreSQL container and apply database migrations
docker compose -f infra/compose.yaml up -d
uv --directory apps/api run alembic upgrade head

# Start FastAPI development server on port 8000
pnpm dev:api
```

### Terminal 2: Start Next.js Web Console
```bash
# Start Next.js development server on port 3000
pnpm dev:web
```

Open your browser to **`http://localhost:3000`** to view the Solo Company Dashboard.

---

## 2. Step-by-Step Walkthrough

### Step 1: Edit the Sample Company
1. On the main Dashboard, click **Company Settings** in the navigation header (or navigate to `http://localhost:3000/settings/company`).
2. Review the company profile for **Solo Company**.
3. In the **Working Rules** textarea, edit the text to specify:
   > *"Specialist work is sequential. Every deliverable must be validated before the next item begins. Standard pricing tier is $499/month."*
4. Click **Save Changes**. Verify that a confirmation notification appears and your edits persist.

### Step 2: Submit “Create a launch plan for a bookkeeping service”
1. From the Dashboard, click **+ New Objective** (or navigate to `http://localhost:3000/objectives/new`).
2. Fill in the intake form:
   - **Title**: `Create a launch plan for a bookkeeping service`
   - **Desired Outcome**: `A go-to-market launch brief, operational onboarding checklist, and executive pricing decision brief.`
   - **Context**: `Targeting small professional services firms with 1-10 employees.`
   - **Constraints**: Add two constraints:
     - `Budget must remain under $5,000 for launch tooling`
     - `Onboarding time must be under 3 business days per client`
3. Click **Generate Plan with Chief of Staff**.
4. Observe the progress status change from *“Creating objective...”* to *“Generating proposed plan from Chief of Staff...”*, followed by an automatic redirection to the Plan Review page.

### Step 3: Approve a Three-Item Plan
1. On the **Plan Review Page** (`http://localhost:3000/objectives/[id]/plan`), review the proposed sequential plan generated by the Chief of Staff agent. You will see three time-ordered work items:
   - **Item 1**: *Draft bookkeeping launch marketing brief* (assigned to **Marketing Specialist**)
   - **Item 2**: *Create client onboarding checklist & SLA* (assigned to **Operations Manager**)
   - **Item 3**: *Synthesize launch executive brief* (assigned to **Chief of Staff / Business Strategist**)
2. *(Optional)* If you wish to test revision loops, enter feedback in the text box and click **Request Revision** to see the plan regenerate.
3. Click **Approve Plan & Execute**.
4. The frontend generates a unique UUID `Idempotency-Key`, submits your approval, and immediately redirects you to the **Run Inspection Timeline** (`http://localhost:3000/runs/[id]`).

### Step 4: Watch Three Work Items Complete
1. On the **Run Inspection Page**, observe the live event timeline populating via real-time Server-Sent Events (SSE):
   - `#1 run.created`: Started Phase 1 run for bookkeeping launch objective.
   - `#2 plan.proposed`: Chief of Staff proposed 3 sequential work items.
   - `#3 plan.approved`: Owner approved launch plan without revisions.
   - `#4 artifact.created`: Created marketing brief.
   - `#5 work.started` & `#6 work.progress`: Operations Manager started client onboarding checklist.
2. In the top header, verify that the run status updates to **Running** (and subsequently to **Completed** when all items finish).
3. Open a separate browser tab to the **Work Board** (`http://localhost:3000/work`) to see the Kanban columns reflect the progress of each deliverable across `Proposed`, `Running`, and `Done` columns.

### Step 5: Open Two Artifacts and the Executive Brief
1. Return to the **Run Inspection Page** (`http://localhost:3000/runs/[id]`).
2. In the right-hand **Run Artifacts** column, you will see the persistent markdown outputs produced by the specialist agents.
3. Click **Bookkeeping service launch brief** (Marketing Brief):
   - A modal card smoothly opens displaying the full markdown report, including Executive Summary, Target Audience, and Launch Milestones.
   - Click **✕ Close**.
4. Click **Launch Executive Decision Brief** (Executive Brief):
   - Review the final decision brief synthesized by the Chief of Staff, recommending the **$499/month** pricing tier and summarizing specialist findings.
   - Click **✕ Close**.

### Step 6: Reload the Page and See the Same State
1. While on the **Run Inspection Page**, press **Cmd+R** (macOS) or **Ctrl+R** (Windows/Linux) to perform a full browser refresh.
2. Verify that:
   - The run ID and title remain unchanged.
   - All event timeline entries appear in the exact same sequence.
   - All generated markdown artifacts remain accessible in the right-hand column.
   - No data was lost or duplicated.

## 3. Testing Retry and Failure Recovery (Optional)
To observe how the system handles transient specialist failures and same-run retry:
1. Navigate back to the Dashboard and open the sample run marked **Failed** (or run `30000000-0000-4000-8000-000000000003`).
2. Observe the red badge indicating a specialist timeout (`ERR_SPECIALIST_TIMEOUT`).
3. Notice that completed work items and artifacts from earlier steps in the run remain intact.
4. Click the **🔄 Retry Run** button:
   - A fresh `Idempotency-Key` is transmitted.
   - The run resumes from the failed work item without repeating previously completed work.
